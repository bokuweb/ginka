# CLAUDE.md

**This project's agent instructions live in [`AGENTS.md`](AGENTS.md). Read it first, then [`docs/roadmap.md`](docs/roadmap.md) — [`docs/ui.md`](docs/ui.md) for anything that renders, and [`docs/connectors.md`](docs/connectors.md) for anything that talks to Slack.**

Quick orientation:

- **Ginka** is an IDE-agnostic coding-agent orchestrator written in Rust on **GPUI**. It targets the feature set of [band-app/band](https://github.com/band-app/band) as a native single binary, borrowing interaction ideas from [Orca](https://www.onorca.dev/). Everything in it is written here: no code is copied or ported in from another project.
- **State of play:** the daemon, wire protocol, Claude/Codex drivers and the ACP driver (Gemini CLI, OpenCode), persistent transcript/composer, checkpoints, review diff, terminals, fan-out, schedules, usage and packaging for macOS and Linux are in, and the CLI, app, MCP bridge and Slack connector share the daemon surface. ACP raises permission requests as questions, and Claude raises tool approvals, its own questions and plan approval over `--permission-prompt-tool stdio`; Codex runs over its app server and raises command and file approvals and its own questions there. `AGENTS.md` § Current state is the short version; `docs/roadmap.md` §5 is authoritative.
- Architecture in one line: a **GPUI app** and a **`ginka` CLI** both talk to a background **`ginka-daemon`** over authenticated WebSocket RPC; the daemon owns SQLite, agent processes, PTYs and git.
- Completed-turn **Undo**, `ginka checkpoint undo <checkpoint>` and MCP `ginka_undo_turn` restore starting files and partial staging through the daemon. Later file/index edits, changed HEAD/branch and agents in overlapping workspace roots refuse undo; a recovery checkpoint is retained before mutation. Unsupported Git states keep ordinary restore.
- Selected-file commits use Git-surface checkboxes, repeatable `ginka commit --path <file>` or MCP `ginka_commit.paths`. They commit full selected contents, retain unrelated staged hunks and run normal hooks through a private index transaction. `--generate` describes that selection; staged-only and amend cannot be combined with it. MCP `ginka_generate_commit_message` returns the same scoped message without committing, and request ids correlate results across simultaneous clients.
- Workspace folders are project-local sidebar labels stored by the daemon. Assign or clear them from the row menu, palette, `ginka workspace folder <workspace> [name]` or `ginka_workspace_folder`; omitting the name clears it. The searchable picker reuses existing labels, including archived-only folders; `ginka workspace folders <project>` and `ginka_workspace_folders` report active/archived counts. Shift ranges and keyboard row toggles select several visible rows for an atomic folder move; `ginka workspace folder-many <project> <workspace>... [--name <name>]` and `ginka_workspace_folders_set` share that daemon request. The selection toolbar also pins or unpins every selected row atomically; `ginka workspace pin-many <project> <workspace>... [--off]` and `ginka_workspaces_pin` use the same operation. Archive and Restore apply an explicit state to every selected row through `ginka workspace archive-many <project> <workspace>... [--restore]` and `ginka_workspaces_archive`; expanded archived rows share selection and folder controls, and collapsing them drops hidden selections. Archive changes metadata only, retaining files, git identity, pins, labels and conversations. Pins lead the folder groups, and labels survive branch changes, archive and restart. Keyboard-focusable headings collapse unpinned active members, saving exact project-local preferences in `app.json`. Search temporarily reveals matching rows without changing saved visibility; hidden rows leave selections, frozen picker targets and keyboard navigation.
- UI: a three-column agent workstation (session sidebar / transcript + composer + terminal dock / right-panel surfaces) on a dark glass surface, specified in `docs/ui.md`. Built on **`gpui-component`**, with **`bezel`** as a design reference we rebuild from, never copy — the two link incompatible `gpui` forks and must never both appear in `Cargo.toml`.
- The seventeen requirements that shape the interfaces (steering, absorbable option changes, three-ref checkpoints, externalised attachments, the daemon-host path rule, accounts per provider, …) are `docs/roadmap.md` §3.3, as N1–N17. Accounts and rate-limit headroom have their own design in `docs/accounts.md`.
- Everything written into this repository is **English** — code, rustdoc comments (`///` on every public item), docs, commit messages and PR titles/descriptions.
- The non-negotiable rules (daemon owns state, domain logic in `ginka-core`, CLI and UI share one protocol, workspace id derived from an immutable worktree `name`, virtualized streaming surfaces, one normalized `AgentEvent` stream, local-first) are spelled out in `AGENTS.md` § Architectural rules.

When a change alters architecture, data model or scope, update `docs/roadmap.md` — including its decision log — in the same change.
