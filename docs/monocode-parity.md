# MonoCode capability map

This is a behavioural inventory of [MonoCode](https://github.com/hardbeat920/monocode),
not an implementation source. It was first read at release 0.1.44 and reviewed
again through main commit
[`08ba69d`](https://github.com/hardbeat920/monocode/commit/08ba69da65b0d252fa49cb4548c5c9b13a884fe7).
Ginka implements the requirements in its own architecture: a daemon owns all
durable state, every capability crosses the shared protocol, and a workspace is
the worktree-sized task identity.

The statuses describe Ginka at 2026-09-28:

- **Done** means a usable vertical path exists, even when polish remains.
- **Partial** means the domain/protocol or a narrower UI is present.
- **Planned** means the roadmap already schedules it.
- **Candidate** is useful prior art that needs a product decision before scope.
- **Out** conflicts with Ginka's stated v1 non-goals.

| --- | --- | --- |
| Providers | Claude Code, Codex, Cursor, Grok Build, OpenCode, Pi, omp and fx; installed-CLI discovery; provider enable/disable; default and custom models | **Partial.** Claude and Codex run today, and Gemini CLI and OpenCode run through one ACP driver (`driver::acp`) with streamed text, thinking, tools, plans and permission questions. The searchable provider/model popover reads the driver catalogues; Codex uses live `model/list`, both drivers retain an offline fallback, and recent model/effort/tier choices are restored. Cursor, Grok, Pi and omp wait on ACP in a version that can be checked; a provider settings UI is M4. |
| Conversations | Streaming sessions, resume, rename, delete, archive, pin, filters, folders, multi-select, recent-session restoration | **Partial.** Streaming/resume/rename/delete and workspace archive are done, and each sidebar row now carries its own menu — rename in place, pin (pinned rows lead the list with a mark), archive — with *Restore* on archived rows. A row names the conversation by its own title where it has one. The sidebar fuzzily searches title, model, provider, project and branch, and a status chip narrows it to working, waiting or finished sessions (⌘1–9 follow what is shown). Open conversations are tabs across the centre column (⌘T, ⌘W, ⌃Tab), restored on the next launch. A sent prompt can be edited and run again: the worktree rewinds to before it and the conversation forks onto a fresh thread, keeping the original. Folders and multi-select remain M4 candidates. |
| Parallel work | Multiple tabs and windows, split conversation panes, background agents and subagents | **Partial.** Ginka runs concurrent workspace sessions and fan-out: the composer's *Try several ways* asks one prompt in a worktree per attempt — several agents, several times each — and a compare view sets the attempts side by side with their state, diff size and last answer, where *Keep* archives the others and *Merge* first merges the winner into the branch the project is on (`ginka workspace merge`). Claude delegated-agent calls now stay in one parent row with a bounded, live trail of their reasoning, messages and tools. Codex child threads wait on its app-server transport; split panes and agents that outlive a turn remain planned. |
| Composer | Multiline drafts, drag/drop/paste attachments, image preview, `@file`, `/command`, provider skills, plan mode, context compacting | **Partial.** Durable drafts, bounded file mentions and merged commands exist. The paperclip, file drop and clipboard-image paste all upload through the daemon-owned store, show removable chips with signature-checked bounded image thumbnails, and permit an attachment-only prompt. While a turn runs, an empty draft offers Stop and a written or attached follow-up offers Send through the existing steer-or-queue policy. Codex context can be compacted from an idle conversation through a provider-gated control; plan approval still needs a shipping driver to raise the native interaction. |
| Follow-ups | Steer a running turn or queue messages; edit, remove, reorder and force-send queued prompts | **Done** for the current transports. The daemon owns stable queue rows and pushes every mutation; the window shows them above the composer, and UI, CLI and MCP can edit, remove and reorder them. *Send now* injects only when the live transport advertises steering and preserves the row on refusal; queued text enters the transcript when it actually dispatches. After opencodex and the Codex CLI: the queue is stored (migration 0013) and survives a daemon restart held; a Stop or a failed turn *holds* it instead of throwing it away, with Hold/Resume and Clear on the card; *Interrupt & send* stops the running turn and sends the chosen row next while the rest keeps its order; ⌘↩ queues even where the turn could be steered; and a sidebar row says how many prompts wait. |
| Interactive input | Permission approvals, agent questions, plan review/edit/approve, nested-agent input routing | **Partial.** The daemon now tracks open request ids, pauses the session, delivers a typed response into the live transport, persists the resolution, and rejects stale cards; UI, CLI, MCP and Slack share that path. A scripted transport pins the loop. ACP raises permission requests; Claude raises tool approvals as Allow/Deny cards, its `AskUserQuestion` as a question with its own choices and `ExitPlanMode` as a plan card, answered on its stdin (`--permission-prompt-tool stdio`). Codex runs over `codex app-server` and raises command and file-change approvals (Allow / Allow for this session / Deny) and its `requestUserInput` questions; persistent (always) scopes are not represented. |
| Transcript | Markdown and code, reasoning/tool activity, tool diffs, failed-tool details, nested agent activity, task lists, copy, quote-to-chat, prompt outline, search | **Partial.** Markdown/activity folding, delegated-agent rows, daemon-side search, whole-message and exact selected-range quote-to-chat exist. A compact floating action appears for meaningful selected text, the command palette retains the range before taking focus, and blank selections fall back to the owning message. Safe workspace file locations in settled prose link to the Files editor without rewriting fenced code. A bounded prompt outline jumps directly to top-level user turns without mistaking interaction-card answers for new prompts. Claude and Codex task snapshots share one bounded live Tasks card whose provider-internal tool rows stay hidden; task labels produce readable persisted-search excerpts, and the latest status-bearing snapshot carries into a bounded cross-provider handoff. |
| Context and usage | Per-turn model/provider provenance, context-window meter, manual compact, provider rate-limit windows | **Done** for the two current providers' reported capabilities. The composer combines live cumulative session tokens, provider-reported current context occupancy and per-account headroom without treating one as another; values update from turn pushes and rate-limit windows refresh on click. Every completed-turn divider retains the provider, model, reasoning effort and service tier that started it, including a provider-reported model refinement, and says how long the agent worked and when it finished. Context occupancy appears only when both used tokens and capacity were reported. Codex additionally advertises manual compaction; the idle-only UI, CLI and MCP operation stays hidden or fails explicitly for providers that do not expose it. |
| Handoff | Change provider while retaining a bounded recap; cross-provider plan build | **Done** for conversation fork/handoff from CLI/MCP and from any completed turn in the window; plan build UI is not. A conversation begun in the `claude` or `codex` CLI outside Ginka can be adopted into a workspace (home screen, palette, `ginka session adopt`) and continues the same vendor thread — Orca reaches the same sessions through its session index and a terminal resume. |
| Second opinion | Send a completed answer to another provider in a split pane | **Done** as a fork: a turn's footer offers *Second opinion* per other agent, which forks the conversation there with a request to review the work; the answer is its own tab rather than a split pane. |
| Checkpoints | Snapshot a session, exact session diff, undo while preserving pre-existing edits | **Done** in the three-ref checkpoint model and turn-scoped changes; UI polish remains. |
| Projects/worktrees | Open git repos or folders, project rail, per-session worktrees and branch creation/switching | **Done** for git/plain projects, scratch workspaces and worktrees. Registration is a name-and-source-folder modal; the sessions column appears only for the selected project. The context-bar branch picker fuzzily switches or creates branches and explains branches held by another worktree. A repository's `.worktreeinclude` (Orca's) lists ignored files — `.env`, local config — copied into each new worktree. Project appearance beyond its display label remains a candidate. |
| Files/editor | File tree, quick/full-text search, syntax editor, linting, save/find/replace, file tabs, markdown/image preview, selection-to-chat | **Done.** A bounded expandable file tree, file/path/content search, conflict-safe saves, find/replace, independent file tabs, back/forward visit history, live-buffer Markdown preview and bounded local PNG/JPEG/GIF/WebP preview exist. A saved selection adds its exact line location to chat; any current-buffer selection can be pasted unchanged into a daemon terminal, opening one when necessary. Installed local language servers add tested stdio transport, versioned changes, hover, workspace-local definitions across tabs and diagnostics, with syntax-only fallback. |
| Source control | Staged/unstaged and hunk diffs, stage/unstage/discard, commit, pull/push/sync, history graph, PR creation, line comments | **Partial.** Unstaged and staged diff sections, per-file and per-hunk stage/unstage/discard, commit, push, safe pull, bounded recent history and batched line comments are done across the window, CLI and MCP. Exact hunk operations regenerate current state and refuse stale headers; discard reverses only worktree-versus-index state so staged edits survive. The window confirms destructive discard in two steps. Pull fetches the configured remote and fast-forwards only after refusing dirty work. The history draws as a lane graph from those parent ids, and a row opens a read-only view of what that commit did (`ChangeSource::Commit`, hex ids only). *Amend* folds work into a last commit that is not yet on a remote (`ginka commit --amend`, MCP `amend`). *Create PR* — and *Commit & Push* / *Commit & Create PR* in the commit box — pushes and opens a pull request through `gh`, answering with its address — an existing one's included — in the window, `ginka pr` and the PR box. *Sync* brings the branch level with its remote in one action — publishing a branch never pushed, otherwise fast-forwarding and pushing what is ahead — from the Git surface, `ginka sync` and MCP (`ginka_sync`). |
| Terminal | Embedded PTYs, persistent terminal tabs, dock positions, close-running confirmation | **Partial.** Daemon-owned PTYs, an empty-dock action for the first shell, a horizontally scrolling keyboard-focusable tab strip with fixed actions, state-aware command-palette actions, mode- and modifier-aware keyboard encoding, platform-correct safe ordinary/bracketed clipboard paste, stable creation order, reattach and bounded replay are done. Two-pane splits create a second daemon PTY, expose an accessible other-pane focus control and synchronize both widths; selecting or keyboard-cycling to a hidden tab replaces the focused pane without collapsing its neighbour, and the pair and active pane restore per workspace while both PTYs remain alive. The bounded scrollback is browsable and live-searchable by mouse or keyboard, reports its offset, preserves the selected result as output arrives, highlights that result and has an accessible jump to live output. Safe file locations in terminal output are keyboard-focusable links into the Files editor, including line/column selection. Closing a live shell requires an accessible second activation and is cancelled by moving to another tab. Arbitrary nested and draggable splits remain with the M4 DockArea work. |
| Search/navigation | Global search across files/projects/transcripts, quick open, back/forward history, keyboard project/session navigation | **Partial.** Command palette, workspace/project-wide file search, semantic indexing and daemon-side open-conversation search with ⌘F/⌘K, excerpts and previous/next jumps exist. Project hits switch to their owning workspace before opening, ⌘1–9 selects the corresponding visible active session, and bounded back/forward history crosses project homes and sessions while skipping removed targets. *Search everywhere* (⌘⇧F, or the palette) is one results list across every conversation and the project's file paths and lines, grouped, newest conversation first and at most two lines per conversation; a conversation hit opens that conversation already searched for the same words, and a file hit opens the Files editor. |

Creation and host-aware reveal remain. |
| Notes | Local markdown notes, tags/search, images, transcript selection to note | **Partial.** Markdown notes are kept by the daemon (migration 0012), per project or loose, and reached from the project rail, `ginka notes` and MCP (`ginka_notes`, `ginka_note_save`). Tags are normalized on write, searchable with the title and body, and can be matched exactly through the CLI, MCP and daemon. | Notifications | Completion/input-needed desktop notifications, sound controls, dock badges | **Done** on macOS. A session moving out of work — finished, failed or waiting on the reader — posts a desktop notification while the window is in the background (macOS; Settings turns it off). Orca's keep-awake holds idle sleep off for as long as an agent's process lives (`caffeinate -w`, daemon setting `keep_awake`). Each kind of news plays its own system sound (Settings turns sounds off), and the Dock badge counts the sessions waiting on the reader. |
| Quick commands | Saved shell commands and prompts, run from anywhere; per-project setup scripts | **Done.** Quick commands are daemon state (migration 0014), per project or global: a shell command opens a terminal named after it and ends in a login shell, a prompt command is sent through the composer. A project's setup commands run in a "setup" terminal after the worktree is made instead of blocking it. |
| Reminders/automation | One-shot session reminders with persistent notices | **Different shape.** Cron jobs run a prompt as a new conversation or a command in a terminal, in a workspace or the project's checkout, with overlap-skip, a precheck that skips a firing its probe says is pointless (Orca's), and run history (`ginka cron`, MCP, Settings → Scheduled). Terminal copying now prefers an exact mouse-drag selection and falls back to the visible viewport; reverse drags and multiline ranges preserve their character and line boundaries. A non-blank terminal selection can be quoted into an existing chat draft from the toolbar or command palette.

## Implementation order

Parity is not a request to reproduce every surface. Work proceeds in vertical,
test-first slices that strengthen Ginka's core loop:

1. Workspace archive/restore, preserved through git reconciliation and exposed
   over protocol and CLI; the existing sidebar archive section consumes it.
2. Model/effort/tier picker and recent choices, using the existing driver-owned
   option policy and catalogue probes. The live typed catalogue and recent
   model are done. Model/effort/tier selection now persists into every turn of
   new and existing conversations, and the driver decides whether the provider
   thread absorbs a live change. A `restart_required` answer now creates a new
   provider thread and carries the normalized transcript as a bounded digest.
3. Native plan/approval/question flows through `RespondToAgent`. The daemon,
   clients and scripted pausing transport are done, and ACP, Claude (stdio
   control protocol) and Codex (app server) raise the normalized requests.
4. CodeEditor integration: edit/save is done with daemon-owned atomic writes and
   optimistic revision checks. Find/replace and saved selection-to-chat with
   exact file-line mentions, independent tabs, back/forward visit history and
   live-buffer Markdown preview and bounded local image preview are done. LSP
   server selection, bounded JSON-RPC transport, live-buffer changes, hover,
   diagnostics and workspace-local definition navigation across tabs are wired.
5. Unified search results and transcript jump, keeping the daemon-side search
   bound and virtualized.
6. Notifications and scheduler UI after the action states are reliable enough
   that a notification can take the reader to the exact pending request.
7. Delegated-agent activity: Claude's recorded `stream-json` shapes now become
   provider-neutral parent/step/finish events. Steps merge by provider id,
   orphan child output is dropped, open children settle at the turn boundary,
   and both text and retained history are bounded. Codex remains deliberately
   deferred until its app-server child-thread notifications replace the current
   `exec --json` transport; guessing an undocumented shape would violate R6.

Each slice starts with a failing domain or service test. UI-only behaviour goes
in `ginka-ui` when it can be tested without a window; view builder chains stay
in `src/`.
